rendering, and a collection of interface fixes. There is also a new relative
mouse API for plugins, and yes, you can now play Freedoom in an editor tab.

## Plugin Manager 2.0 And Startup Transactions

Updating plugins on Windows can get complicated when a font, language server
or native library is still open. Replacing those files while the editor is
using them can fail halfway through an operation.

Plugin Manager 2.0 queues Windows installs, upgrades and removals for the next
full launch instead. The **Pending restart** filter lets you review or undo
your selections without downloading anything. After closing all Pragtical
instances and reopening the editor, ppm prepares the complete batch before
replacing the installed files. A soft restart does not apply these changes.

If another process still holds a file open and the changes can be rolled back
safely, the update stays queued. Close the program named in the startup
window, then relaunch Pragtical to retry. Preparation failures leave the live
plugins unchanged and the selection available to edit.

![The startup transaction window downloading and preparing queued plugin changes on Windows](/img/blog/v3160/startup-transactions.png)

The screenshot comes from [PR #731](https://github.com/pragtical/pragtical/pull/731).
Download progress now shows received bytes, and the total and percentage when
available, both here and in Plugin Manager. Linux and macOS keep applying
operations directly. Windows also gets long-path support and better recognition
of bundled Lua files whose only difference is their line endings.

The new [core.transactions API](/docs/api/core.transactions) is available to
other plugins too. It runs queued handlers before normal editor initialization,
supports progress reporting and retry requests, and prevents multiple editor
instances from executing the queue at once.

## Faster SDL GPU Rendering

Font zooming should feel considerably better with the SDL GPU backend. Glyph
uploads are batched, and staging buffers and atlas textures are reused instead
of repeatedly allocating them as font sizes change. In the measurements from
[PR #725](https://github.com/pragtical/pragtical/pull/725), zoom draw time dropped
from 126.8 to 7.7 ms on Windows/D3D12, and from 14.5 to 4.6 ms on Linux/Vulkan.

Dense drawing updates also avoid repeated command hashing and replay scans,
including when the command list grows or shrinks. Caching the backend options
removes environment lookups from the rectangle drawing path. With dense replay
already corrected, that caching reduced the eight-cube benchmark from 3.43 to
1.46 ms on Linux/Vulkan, about 3.69 times faster than the Surface backend in
that test. These are workload-specific timings, not whole-editor speedups.

One detail for anyone experimenting with renderer flags: `PRAGTICAL_SDLGPU_*`
options are now read once when the backend is first selected. Changing them
requires closing and reopening Pragtical; **Restart** inside the editor does
not reread the environment. See the [renderer guide](/docs/user-guide/renderer-backends)
for the backend choices and diagnostic options.

## Interface And Wrapping Fixes

Search and replacement fields, project-search include/exclude filters, audio
filtering, and custom Settings list filters now have clear buttons. This makes
it easier to get back to the full list without selecting and deleting a query.

Settings scrollbars stay at the outer edge of their pane, with section
separators drawn inside the scrolling area. On Windows, custom borderless
outlines no longer compete with the native border and rounded corners.
The outline also has its own `style.outline_size`, independent of split
dividers and scaled with the rest of the interface. The title-bar and welcome
logos now use the current theme's colors.

Thanks to [bananakid](https://github.com/bananakid) for
[reporting and testing the Settings and window-outline issues](https://github.com/pragtical/pragtical/issues/721).

Right-click menus once again open slightly away from the pointer instead of
putting their first item directly underneath it. Thanks to
[Kabcorp](https://github.com/Kabcorp) for [reporting the regression](https://github.com/pragtical/pragtical/issues/724).

Whitespace markers now follow the correct visual row when word wrapping is
enabled. Runs of spaces and tabs are split at wrap boundaries, so their
markers no longer overlap earlier rows. Thanks to
[skotarek](https://github.com/skotarek) for [the report and reproduction](https://github.com/pragtical/pragtical/issues/737).

## Wayland Window Activation

Opening a file in an already running editor now forwards the launcher's
`XDG_ACTIVATION_TOKEN` over IPC before raising the existing window. The desktop
entry also enables startup notification so launchers can provide fresh tokens.

Full activation needs SDL's [RaiseWindow token fix](https://github.com/libsdl-org/SDL/pull/16693)
and a valid token from the launcher. The pinned SDL 3.4.20 does not include that
fix, so forwarding alone does not resolve activation in builds using that
unpatched dependency.

Thanks to [palant](https://github.com/palant) for
[reporting and investigating this behavior](https://github.com/pragtical/pragtical/issues/696),
and [ErEbusE](https://github.com/ErEbusE) for pointing out the upstream fix.

## Relative Mouse Input And Freedoom

Plugins can now use
[`renwindow.set_relative_mouse_mode()`](/docs/api/renwindow#set_relative_mouse_mode)
and [`renwindow.get_relative_mouse_mode()`](/docs/api/renwindow#get_relative_mouse_mode)
without relying on SDL symbols being exported by the executable. This works
with statically linked SDL too. Relative mode hides and constrains the pointer,
providing continuous movement even at the window edges. Plugins must release
it when paused, closed, or losing focus.

One use for that API is the new [Freedoom for Pragtical](https://github.com/pragtical/freedoom)
port. It runs Freedoom and FreeDM inside an editor tab using Woof or Odamex,
with sound effects and MUS/MIDI music through Pragtical's audio API. It also
supports multiplayer, including Woof co-op/deathmatch and Odamex server browsing.

Install **Freedoom for Pragtical** from Plugin Manager, then run
**Freedoom: Open** from the command palette. Click the game to capture the
mouse and press **F12** to release it. LuaJIT is required; packages include
native engines for Linux and macOS on x86_64/aarch64, and Windows on x86_64,
plus the free game data. This is an optional plugin, not part of the editor's
default installation.

Thanks to the Freedoom, Woof and Odamex contributors for making this possible.
The plugin is independent of those projects. Use trusted game data and mods:
the engines run inside Pragtical's process, so an engine crash can also close
the editor.

## Updated Plugins And API Reference

The catalog update includes Ghostty 0.4.0, Terminal 2.0, SCM 0.10.0,
LSP 0.17.11, Web Browser 0.2.0, Media Player 0.3.0, and Build and Debugger 0.4.0.
Modal now points to the Pragtical fork, and the unmaintained Vibe plugin is
removed from the catalog.

Thanks to [irisdominguez](https://github.com/irisdominguez) for
[updating Link Opener to 0.1.5](https://github.com/pragtical/plugins/pull/69),
including its bug fixes.

The [API reference](/docs/api/core) has also been regenerated with the current
editor and Widget declarations, including startup transactions and relative
mouse input. Thanks to everybody who tried the rolling builds, reported
problems and helped test the changes!

Downloads on [GitHub](https://github.com/pragtical/pragtical/releases/tag/v3.16.0).
