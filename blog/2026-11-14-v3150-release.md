Pragtical v3.15.0 improves how the editor handles fonts, Unicode text and
rendering, while making Settings easier to search and reset. It also adds
workspace recovery checkpoints, more predictable line wrapping, richer
clipboard support, and a native MSVC build for the Windows packages.

## Automatic Font Fallback And Unicode Editing

Missing characters should no longer require hunting down the right fallback
font yourself. When your configured fonts cannot display a grapheme, Pragtical
can now ask the operating system for an installed font that can. Your explicit
font choices still take priority.

The implementation uses DirectWrite on Windows, CoreText on macOS and
Fontconfig on Linux. Fontconfig is loaded at runtime, so Linux builds still
work without it, but then missing characters need explicit fallback fonts.
Other Unix-like systems with Fontconfig may work, but have not been tested.

The follow-up work fixes color and tag flags, rejects fonts that advertise a
character but only draw a blank glyph, and falls back to individual components
when an emoji sequence has no combined glyph. Failed lookups and glyph renders
are cached too, so scrolling does not repeatedly try the same unsupported
sequence. In a warm Linux emoji-scrolling test, the 95th-percentile frame time
fell from about 113 ms to 5 ms; this is a specific workload, not a general
performance guarantee.

Editing now follows the same grapheme boundaries as rendering. Moving the
caret, deleting text and wrapping lines keep combining marks, variation
selectors and composed emoji together rather than stopping inside a displayed
character. Boundary caches are updated near an edit instead of rescanning the
whole line.

Thanks to [palant](https://github.com/palant) for
[requesting automatic font fallback](https://github.com/pragtical/pragtical/issues/710).
The [font configuration guide](/docs/user-guide/configuration#automatic-font-fallback)
and [Color Emoji guide](/docs/user-guide/color-emoji) explain the available
font priorities and fallback options.

## Searchable Settings And Individual Resets

Core and Plugins settings now have search fields that stay visible while
their sections scroll. Filtering keeps the existing controls instead of
rebuilding the interface, so you can find an option without losing an edit.

Individual settings also have Reset actions. Reset removes the saved GUI
override, restoring the default instead of writing another copy of it. Color
settings can therefore follow the current theme again. The action disappears
when there is no saved override left to remove.

make the font fail to load and later overwrite the saved choice with the
default. Thanks to [AmerM137](https://github.com/AmerM137) for

## Wrapping And Caret Placement

Soft wrapping now uses the shared **Line Limit** by default, or the viewport
width when it is narrower. This makes wrapping line up with document centering
and the column guide. Viewport-only wrapping is still available by disabling
**Settings > Plugins > Line Wrapping > Wrap At Line Limit**.

Word wrapping no longer treats leading indentation as a place to break before
an oversized first word. Here is the corrected result from
[PR #671](https://github.com/pragtical/pragtical/pull/671):

![Indented words stay together instead of leaving an empty wrapped row](/img/blog/v3150/wrapping-after.png)

Mouse positioning also follows the visible wrapped rows and character
boundaries, including the final column and documents with folded regions.

The new `doc:center-cursor` command scrolls the current caret into the vertical
center of its view. It follows the caret's wrapped row, not just the first row
of its document line. The default binding is **Alt+V** on Windows and Linux;
macOS leaves it unbound because Option+V produces a character there.

Thanks to [AmerM137](https://github.com/AmerM137) for
[implementing the centering command](https://github.com/pragtical/pragtical/pull/688),
[bananakid](https://github.com/bananakid) for the
[column-wrapping request](https://github.com/pragtical/plugins/issues/40), and
[ancient-dinosaurus](https://github.com/ancient-dinosaurus) for reporting the
[indentation break](https://github.com/pragtical/pragtical/issues/656) and
[last-column mouse positioning](https://github.com/pragtical/pragtical/issues/705).

## Less Idle Work And Faster Rendering

The work to reduce idle CPU usage continues. Views request updates for input,
animations or timed work instead of updating on every idle frame. The new
`core.request_update(delay)` API lets plugins schedule their next update, and
the scheduler preserves pending work through input events and exact frame
deadlines. This also fixes menus and other animations stopping halfway open
when the pointer stops moving.

In the focused-editor check shared with
[PR #652](https://github.com/pragtical/pragtical/pull/652), CPU usage fell from
3.25% to 1.01% of one core with caret blinking enabled, and from 2.94% to 0.44%
with it disabled. Results depend on the workload and enabled plugins.

The rendering cache now tracks smaller damaged regions and skips draw commands
that cannot affect them. Large unchanged SDL GPU scenes can remain cached
without sacrificing dense updates. In the Linux/X11 benchmark from
[PR #697](https://github.com/pragtical/pragtical/pull/697), using 1,800 text draws
at 1600x1000, the SDL GPU static-frame time fell from 1.361 ms to 0.184 ms and
the caret-only case from 1.286 ms to 0.515 ms. Scrolling and fully changing
frames stayed within trial variation, and before/after captures were
pixel-identical.

SDL GPU pixel uploads also avoid an extra staging copy. Local 720p and 1080p
pixel-streaming benchmarks measured about 20-23% less CPU time per frame for
that upload path. Polygon fills now use the same FreeType edge coverage as
the surface renderer, correcting self-intersecting shapes and oversized
antialiased edges. Canvases queued for drawing remain alive until their frame
finishes, even if LuaJIT's garbage collector runs first.

The native tokenizer reuses indexing and completed tokens across resumes and
avoids repeated scans of the same line. A 1 MB CodeMirror line took 1.33 seconds
instead of 69.93 seconds in one paired native-tokenizer comparison. Smaller
C, Lua and Markdown tests were about 7-35 times faster than the Lua tokenizer;
the [PR #709 measurements](https://github.com/pragtical/pragtical/pull/709)
include the individual inputs and baselines. These are tokenizer timings, not
whole-editor speedups.

Plugin developers can find the scheduling conventions in the
[updates and rendering guide](/docs/developer-guide/writing-plugins/updates-and-rendering).

## Workspace Recovery

Saved sessions now stay on disk while the editor is running. A crash or forced
shutdown no longer removes the session that should be available on the next
start. Sessions are stored per project, and the active session is remembered
across restarts. Workspace directories are saved as absolute paths, with
missing roots skipped and reported instead of breaking restoration.

There is also an optional **Periodically Save Workspace** setting under
**Settings > Plugins > Workspace**. It saves temporary recovery checkpoints of
open tabs and unsaved text, without saving the document files themselves.
It is off by default; the default interval, when enabled, is 10 seconds.

```lua
local config = require "core.config"
config.plugins.workspace.autosave = true
config.plugins.workspace.autosave_interval = 10
```

Thanks to [palant](https://github.com/palant) for
[reporting the lost-session behavior and suggesting periodic recovery saves](https://github.com/pragtical/pragtical/issues/694).

## Clipboard, Storage And Text Fixes

The clipboard API now supports MIME data, including
`system.get_clipboard_mime_types()`. On Linux, pasting files from a file manager
can fall back to `text/uri-list` and insert their paths when plain text is not
available. Native file-list formats on Windows and macOS still need separate
platform support; this does not make that fallback automatic on those systems.

Plugin storage can now target a project or an explicit directory as well as
the user profile. Project-local files accept serialized data rather than
executable Lua. See the [persistent state guide](/docs/developer-guide/writing-plugins/persistent-state)
for the new scope argument and usage examples.

There are fixes for multiline Markdown link highlighting, extra background
padding around inline code in the preview, SVG files without an XML declaration,
XHTML syntax detection, and whitespace markers just outside a selection.
Thanks to [palant](https://github.com/palant) for the reports and suggestions
behind these clipboard and text improvements.

## Borderless Windows And Interface Fixes

Borderless windows have configurable outlines and inactive title-bar tinting,
making the window boundary and focus state easier to see. Windows also gets
shadows with custom decorations. The title bar refreshes when focus returns.

![An unfocused borderless Pragtical window with a visible outline and inactive title bar](/img/blog/v3150/borderless-unfocused.png)

Thanks to [bananakid](https://github.com/bananakid) for the
[borderless-window usability suggestions](https://github.com/pragtical/pragtical/issues/690).
Menus and audio controls now use Fontello icons, including visible unchecked
menu toggles. Thanks to [Vinfall](https://github.com/Vinfall) for
[reporting the menu alignment problem](https://github.com/pragtical/pragtical/issues/676).

Nested dialogs stay above their modal owners and restore focus to the parent
input when closing. SelectBox popups keep their bottom options visible when
reopened after scrolling, including at fractional UI scales. Newly opened
views, closed tabs and resized Widget controls request the redraws they need
instead of waiting for another mouse or keyboard event.

The obsolete command-prompt file-count icon was removed too. Thanks to
[ancient-dinosaurus](https://github.com/ancient-dinosaurus) for
[pointing it out](https://github.com/pragtical/pragtical/discussions/649).

## Windows Builds And Updated Plugins

Official Windows packages now use the native MSVC toolchain for tests, portable
archives and Inno Setup installers, retaining LTO and PGO for rolling and
release builds. The packages include `pragtical.exe` for the GUI and
`pragtical.com` for console commands. MSYS2/GCC remains a supported build route;
the [build guide](/docs/setup/building) covers both.

Thanks to [Omikorin](https://github.com/Omikorin) for
[raising the MINGW64 deprecation issue](https://github.com/pragtical/pragtical/issues/607)
that prompted this toolchain review.

SDL3 is updated to 3.4.20, with the Wayland clipboard ownership fix retained.
Plugin Manager 1.8.0 tracks installed versions and protects local plugin copies
during upgrades. AppImages include a PNG `.DirIcon` for newer packaging tools.

The plugins catalog includes the new optional web browser and libmpv-based
media player, Ghostty updates, Erlang highlighting, and improvements to C3 and
Rust highlighting. These optional tools are installed through Plugin Manager;
they are not new built-in editor views.

Thanks to [0riginaln0](https://github.com/0riginaln0) for the
[autocomplete minimum-length change](https://github.com/pragtical/pragtical/pull/648),
[C3 updates](https://github.com/pragtical/plugins/pull/62), and
[transpose plugin](https://github.com/pragtical/plugins/pull/66). The completion
minimum-length upper bound is removed, allowing larger configured values.
Thanks also to [Vinfall](https://github.com/Vinfall) for the
[emoji keyword groups](https://github.com/pragtical/plugins/pull/68) and
[Fortune fixes](https://github.com/pragtical/plugins/pull/67).

The website's [user guide](/docs/user-guide/introduction) and
[API reference](/docs/api/core) have been refreshed alongside the screenshots.
There is also a new [testing guide](/docs/developer-guide/testing) for writing
and running tests against the editor runtime.

Thanks to everybody who reported issues, tried the rolling builds and helped
test these changes!

Downloads on [GitHub](https://github.com/pragtical/pragtical/releases/tag/v3.15.0).
